# FaithRequest

A prayer request management app for organizing lists, tracking answered prayers, and setting daily reminders. Hosted at [faithrequest.com](https://faithrequest.com).

Frontend pages:

- `index.html` landing page
- `login.html` login page
- `register.html` registration page
- `dashboard.html` authenticated prayer dashboard

## Features

- Create multiple prayer lists with descriptions.
- Add prayer requests with notes and priority.
- Turn daily alerts on or off per request.
- Mark requests as answered or active.
- Receive in-app reminders.
- Optionally enable browser notifications.
- Prayer data is saved in DynamoDB through the backend API.
- Session token and selected list are cached in `localStorage`.

## Run Locally

1. In project root, install frontend tooling:
	- `npm install`
2. Start a local frontend server:
	- `npm run dev:frontend`
3. Open `http://localhost:5500/index.html`.
4. Choose **Log In** or **Register**.
5. After authentication, you are redirected to `dashboard.html`.
6. Create prayer lists or add prayer requests.
7. Set a daily reminder time for requests that need alerts.
8. Click **Enable Notifications** if you want browser pop-up reminders.

## Frontend Runtime Configuration

The frontend reads the API base URL from `config.js`.

- Local development default in `config.js`:
	- `http://localhost:5000/api`
- Production example is included in `config.production.example.js`.

Before deploying static files to AWS (S3 + CloudFront), set `config.js` to your production API URL, for example:

- `https://api.faithrequest.com/api`

## Backend (DynamoDB)

This project includes a backend in `backend/` for storing user data in DynamoDB.

1. Open a terminal in `backend`.
2. Run `npm install`.
3. Copy `.env.example` to `.env` and set `DYNAMODB_TABLE_NAME` (and `AWS_REGION`) to point at a table you have access to.
4. Start the API with `npm run dev`.

API base URL: `http://localhost:5000/api`

Auth + frontend usage:

1. Start the backend in `backend/` with `npm run dev`.
2. Start the frontend in root with `npm run dev:frontend`.
3. Open `http://localhost:5500/index.html` and use landing links to **Log In** or **Register**.
4. After successful auth, use `dashboard.html` to create prayer lists and submit prayer requests.
5. Data is saved to DynamoDB automatically through authenticated API calls.

## AWS Deployment

Live stack (see [CLAUDE.md](CLAUDE.md) for deployed resource names and [docs/adr](docs/adr/README.md) for the decisions):

- Frontend: S3 + CloudFront
- Backend: AWS Lambda + API Gateway (HTTP API)
- Database: DynamoDB
- DNS/TLS: Route 53 + ACM

Deployment assets are included in:

- `backend/lambda.js` (Lambda entry point, wraps the shared Express app in `backend/app.js`)
- `deploy/aws/aws.env.example`
- `deploy/aws/prepare.js`
- `deploy/aws/out/` (generated by the prepare script)

Redeploy flow (infrastructure — the DynamoDB table, Lambda function, API Gateway, S3 bucket, and CloudFront distribution — is created once and not part of this script; see `deploy/aws/README.md`):

1. Copy `deploy/aws/aws.env.example` to `deploy/aws/aws.env` and fill in your AWS values.
2. Run `npm run aws:deploy` from the project root (Windows PowerShell), or `npm run aws:prepare` + the commands in `deploy/aws/out/next-steps.txt` on any platform.
3. Use `npm run aws:deploy:dry-run` to print every command without changing AWS resources.

The prepare step generates a production `config.js` for the frontend and stages static site files for S3 upload; `deploy.ps1` additionally zips `backend/` and updates the Lambda function code.
